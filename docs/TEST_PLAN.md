# 测试计划

## 1. 当前状态与方法

本文件主体是后续待执行测试清单；已执行范围单独记录在第 9 节，不能据此视为整个计划已通过。

测试原则：

- 连续天数算法使用可注入 `Clock` 做确定性测试。
- 数据库唯一约束、事务和 Redis 使用真实 MySQL/Redis 验证。
- UniApp H5 使用真实 REST API 做端到端验收。
- 不用 H2、内存 Map 或前端 Mock 代替真实 MySQL/Redis 的核心验收。
- 测试使用独立数据库、Redis 库和测试账户，不污染正式演示数据。

本计划分为“必做测试”和“可选高级测试”。项目先通过必做测试，再视时间补充高级验证。

## 7. 可选高级测试

这些测试用于加分和增强工程性，不作为第一版完成的前置条件：

| 编号 | 场景 | 目标 |
| --- | --- | --- |
| A01 | 20+ 并发请求重复多轮 | 更强地验证唯一约束和事务冲突处理 |
| A02 | 失败事务后重新读取已有记录 | 验证不会在 rollback-only 事务中错误读取并返回假成功 |
| A03 | Redis 整体不可用 | 新登录/鉴权不能绕过 Session；已有 MySQL 数据保持完整 |
| A04 | 已鉴权后业务缓存不可用 | 回退 MySQL，业务查询和已提交打卡结果仍正确 |
| A05 | 缓存删除失败 | 记录日志；MySQL 成功不回滚；短 TTL 后缓存最终恢复 |
| A06 | 缓存内容损坏 | 按 Miss 处理并重新从 MySQL 构造正确值 |
| A07 | 闰年 | 2028-02-28、02-29、03-01 连续 3 |
| A08 | 极长连续记录 | 例如 400 天 streak，不被固定最近 30/365 天查询错误截断 |
| A09 | 午夜边界 | 午夜前捕获的请求使用旧业务日期；午夜后的新请求使用新日期 |
| A10 | 超大 BIGINT ID | 前端按字符串处理，不发生 JavaScript 安全整数精度问题 |
| A11 | 数据库临时故障/死锁 | 返回真实错误，不吞掉为重复打卡成功 |
| A12 | CORS 与多 Session | 仅允许配置来源；不同 Session 独立固定到期 |

| 场景 | 关键断言或当前已知差异 |
| --- | --- |
| 正常登录及用户名规范化 | 用户名 trim、小写转换；BCrypt 匹配；HTTP 200/code=0，当前 data 仅有 token；不泄露密码哈希 |
| 错误凭证 | 不存在用户与错误密码均为 401/40102，不创建会话 |
| 输入边界 | 空白、缺失、未知字段、损坏 JSON 返回 40001；用户名 3–32 位 ASCII 和密码 8–72 个 UTF-8 字节是待补齐规则 |
| Redis 存储 | Key 只包含令牌摘要，值为十进制用户 ID 字符串；TTL 接近配置值；连续访问不续期 |
| 当前用户 | 有效令牌返回真实 MySQL 用户；客户端 userId 不改变身份；当前 id 为数字，尚不符合字符串契约 |
| 无效身份 | 缺少请求头、错误前缀、空令牌、不存在或过期会话返回 40101 |
| 用户已删除 | /auth/me 返回 40101；目标要求同时删除遗留会话，当前尚未实现，不能标记完整通过 |
| 正常登出 | 200/code=0/data=null；当前会话键消失；原令牌后续访问 /auth/me 返回 40101 |
| 重复及并发登出 | 删除后的令牌重新请求返回 40101；若两个请求都已通过鉴权，删除不存在的键仍可正常完成 |
| 多会话隔离 | 同一用户两次登录产生独立令牌；登出其中一个不撤销另一个 |
| Redis 故障 | 登录写入、鉴权读取、登出删除故障均不能伪装成功；目标为 50301，当前未专门分类，可能得到 50302 或 50001 |
| 损坏会话值及非法 TTL | 非整数会话值和非正 TTL 应有明确处理；当前未专门校验，需记录实际异常与响应 |
